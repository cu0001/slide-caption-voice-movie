# スライドを部品ごとに動かし、ナレーションと字幕を付ける

動画は、字幕の文をそのまま読み上げるナレーション付きが既定です。字幕1つが読み上げの1区切りで、字幕は話している間だけ表示されます。音声は Irodori-TTS（`.env.local` の `IRODORI_URL` のサーバー）で作ります。読み取り・部品の切り分け・文章作成はこのアシスタントが行います。コマンドはすべてこのリポジトリのルートで実行します（初回は `npm ci`。Google Chromeが必要）。リポジトリのルートは、このSKILL.mdがある `.claude/skills/<スキル名>/` の3つ上のディレクトリです。ユーザーのスキル（`~/.claude/skills/`）としてリンクされて別のフォルダから呼ばれたときは、リンク先（`readlink`）をたどってルートを求め、そこへ `cd` してから実行します。

Irodori につながらないとき（手順10で失敗したとき）や、ユーザーが音声なしを望んだときは、手順10を飛ばして手順8の字幕入りプロジェクト（読む速さで時間を割り当てた無音の版）で続けます。その場合は、音声を付けられなかった理由を報告します。

**既定は「部品ごとの動き＋字幕」で、PDF全体を1本の流れ（1つのプロジェクト・1本の動画）にします。** ページ数が多くてもパートに分けません。アプリは字幕の修正と音声の作り直しができるシンプルな作りで、要素の一覧や動きを調整する欄はありません。動きを直したいときは、ユーザーがAIアシスタントに頼み、アシスタントが直します（「動きを直す」を参照）。 PDFのページは1枚の画像として取り込まれるので、そのままではページ全体をカメラで映すことしかできません。このスキルでは、ページを部品（見出し・本文・イラストの中の物など）に切り分けて、それぞれ別の動きで登場させます。切り分けが向かないページだけ、カメラの動きにします（「部品に分けるかどうか」を参照）。

## 入力と出力

- 入力: PDF（40MB・60ページ以内、パスワードなし）、またはアプリの「保存」で保存したJSON。
- 出力先: ユーザーの指定がなければ `output/<入力ファイル名>/`（Gitには含めない）。
  - `project.json`: PDFから作ったプロジェクト（PDF入力のとき）
  - `work/`: 静止画・`slides.json`・`elements.json`・`captions.json`・`check/`（作業用）
  - `elements-project.json`: 部品に分けたプロジェクト（字幕なし）
  - `<名前>-captions.json`: 部品の動き＋字幕入りのプロジェクト（音声なし。字幕は読む速さで時間を割り当てたもの）
  - `<名前>-voice.json`: ナレーション入りのプロジェクト。字幕と部品の登場が音声に合っている（アプリの「開く」で確認できる）
  - `<名前>-voice.webm`: ナレーションと字幕入りの動画（頼まれたとき、またはPDFから動画を作るよう頼まれたとき）
  - `work/readings.json`: この資料のために決めた読み方（手順9）
  - `work/voice/`: 字幕ごとの音声（作り直しのときに、変わっていない字幕の音声を使い回す）
  - `public/examples/startup/`: アプリの起動時に開くプロジェクト（1つ。手順11で毎回置き換える）
- ユーザーの元ファイルは上書きしない。前に作った出力を上書きするときは、上書きすることを報告に書く。

## 手順

1. **PDFならプロジェクトにする**（JSONならこの手順は不要）。アプリの「PDFを読み込む」と同じ処理で、各ページを全画面のスライドにする。

   ```bash
   npm run pdf:project -- <input.pdf> output/<名前>/project.json
   ```

   1ページの秒数は `--seconds 5` で変えられる（既定は4秒）。字幕が長ければ手順8で自動的に伸びるので、通常は既定でよい。

2. **静止画と文字を書き出す。**

   ```bash
   npm run captions:export -- output/<名前>/project.json output/<名前>/work
   ```

   `work/slide-01.png`…、10%刻みの方眼を重ねた `work/slide-01-grid.png`…、`work/slides.json`（各スライドの `id`・見出し・本文・要素の文字・既存の字幕）ができる。PDFページはカメラの動きなしでページ全体を写す。字幕は描かれていない。

3. **すべての静止画を Read で実際に見る。** `slides.json` の文字だけで判断しない。
   - PDFが入力なら、PDFも Read で読む（`pages` でページ範囲を指定）。`slides.json` の `title` はPDFから抜き出した文字の先頭100字だけなので、本文はPDFで確認する。
   - 方眼つきの `-grid.png` で、部品にしたいものの位置（上下左右の端）を読む。
   - 部品の背景の色（台紙・空・机など、部品のすぐ後ろにある面の色）を調べる。目で見た色は不正確なので、ページ画像の画素を読む:

     ```bash
     npm run colors -- output/<名前>/project.json <ページ番号> 0.3,0.5 0.62,0.2
     ```

     座標は方眼と同じ0〜1（ページが16:9のとき）。色を測る点は、部品のすぐ外側の、ほかの物がない平らな場所を選ぶ。画像はChromeで読むので、Pythonの画像ライブラリなど、このプロジェクトの依存にないものは使わない。

4. **`work/elements.json` を書く**（下の「部品の切り分け方」「動きの付け方」）。部品に分けないページは書かない（カメラの動きのまま残る）。

5. **部品に分ける。**

   ```bash
   npm run elements:build -- output/<名前>/project.json output/<名前>/work/elements.json output/<名前>/elements-project.json --check output/<名前>/work/check
   ```

   ページごとに部品の数と「元のページとの差」を表示する。差は、全部品が出そろった瞬間の画面と元のPDFページとの違いで、**0.3%以下**が目安（0.3%を超えると警告が出る）。

6. **確認画像を Read で見て、直す。** `work/check/` に次の2種類ができる。
   - `steps-01.png`…: 0.3秒・0.8秒・1.5秒・出そろった瞬間の4コマ。登場の順番と、部品が来る前に残る跡を確かめる。
   - `bg-01.png`…: 部品をすべて抜いた後の背景。抜いた跡が自然に埋まっているかを確かめる。

   次のどれかがあれば `elements.json` を直して手順5をやり直す。
   - 差が0.3%を超える、または出そろった画面が元のページと違う → その部品の色が背景の色に近すぎる。`tolerance` を下げる（14〜20など）か、`key` の色を見直す。
   - 部品が来る前の画面に、部品の形の跡（縞・輪郭・欠け）が目立つ → `key` に背景の色が足りない、または `box` が別の物にかかっている。`box` を締める、`key` の色を足す、`fill` で穴埋めに使う色を絞る。
   - 部品が台紙の外の色（暗い地色など）を一緒に運んでいる → `box` を台紙の内側に収める。
   - 背景の色と部品の色が同じ部分がある（例: 葉の一部が丘と同じ緑）→ その部品は分けない。色で切り分けると同じ色の部分が背景側に残り、ちぎれて見える。

7. **`work/captions.json` を書く**（下の「字幕の書き方」）。部品に分けなかったPDFページには `motion` も書く（下の「カメラの動きの選び方」）。

   ```json
   {"slides":[{"id":"<slides.jsonのid>","captions":["一文目。","二文目。"]},
     {"id":"<部品に分けなかったページのid>","captions":["一文目。"],"motion":{"type":"zoom-in","amount":0.6,"focusX":0.72,"focusY":0.45}}]}
   ```

   部品に分けたページはスライドの `id` が変わらないので、手順2の `slides.json` の `id` をそのまま使える（`id` の代わりに1から数える `index` も可）。

8. **字幕を書き込む**（ここでは読む速さ毎秒6文字で仮の時間を割り当てる。音声なしで作るときはこの時間のまま使う）。入力は部品に分けた `elements-project.json`。`cue` を付けた部品は、その字幕の始まりに合わせて動く。

   ```bash
   npm run captions:apply -- output/<名前>/elements-project.json output/<名前>/work/captions.json output/<名前>/<名前>-captions.json
   ```

   スライドごとに字幕の数・伸びた秒数・選んだ動きを表示する。
   - 字幕が多すぎる（1スライド21個以上）、長すぎる（1個121字以上）、または表示に60秒を超える（読む速さ毎秒6文字で計算）と、「スライド 2: 字幕の表示に77.3秒必要です。…」のようにスライド番号を出して止まり、ファイルは書き出さない。そのスライドの字幕を減らすか短くして、`captions.json` を直してから手順8をやり直す。字幕は切り詰められないので、内容が勝手に欠けることはない。

9. **読み方辞書を作って登録する**（毎回行う）。Irodori は日本語専用で、英字・略語・難読語・数字を読み間違えやすい。字幕は元の表記のまま残り、音声だけが辞書の読みになる。
   1. 辞書にない英字の語を洗い出す: `npm run reading -- --unknown output/<名前>/work/captions.json`
   2. 読みを決める。英字の語はすべて一般的な読みをカタカナで（`AWS` → `エーダブリューエス`）。複数語の名称はまとまりのまま1語にする（`Red Hat` → `レッドハット`）。読み間違えやすい漢字（固有名詞・専門用語・複数の読みがある語）はひらがなかカタカナで。桁ごとに読ませたい数字（ポート番号など）も登録する。普通に読める語は登録しない。
   3. `output/<名前>/work/readings.json` に `{ "表記": "読み" }` で書き出し（JSONシリアライザーで作る）、登録する: `npm run reading -- --import output/<名前>/work/readings.json`
   4. `--unknown` が「辞書にない英字の語はありません。」になるまで 2〜3 を繰り返し、`npm run reading -- --preview output/<名前>/work/captions.json` で不自然な置き換えがないか確かめる。
   - 辞書の本体は `voice/readings.json`（すべての資料で共通。Gitに含める）。1語だけなら `npm run reading -- 表記 読み` でも登録できる。

10. **音声を作り、字幕と部品の時間を音声に合わせる。**

   ```bash
   npm run voice:generate -- output/<名前>/<名前>-captions.json output/<名前>/<名前>-voice.json
   ```

   字幕を1つずつ Irodori で読み上げ、字幕の表示時間をその音声の長さにする（話し始めは0.5秒、字幕の間は0.4秒あける）。スライドの長さは読み上げの長さで決まり、`cue` の部品はその字幕の始まりに合わせて出る。全体の音声は1本のWAV（24kHz）としてプロジェクトに入る。
   - 最初の1回はサーバーの起動に1〜2分かかる。1文に数秒かかるので、字幕が30個を超えるときはバックグラウンドで実行し、終わったら知らせる。
   - 作った音声は `work/voice/` に残る。字幕の文・読み方・声・話す速さが同じなら使い回すので、作り直しでは変わった字幕だけをサーバーに頼む。
   - 1スライドの読み上げが60秒を超えると止まる。そのスライドの字幕を減らすか短くして、手順7からやり直す。
   - 接続や認証のエラー（`IRODORI_URL`・`gcloud auth application-default login`）は、エラーの文をそのまま報告し、ユーザーに直してもらう。音声なしで先に進めるかも尋ねる。
   - 出力の各行（読み上げ秒数・スライドの長さ・合図で出た部品）を確かめる。

11. **アプリの起動時に開くようにする**（毎回行う）。手順10で作ったナレーション入りのプロジェクト（音声なしで作ったときは手順8のもの）を、アプリを起動したときに開くプロジェクトにする。渡すプロジェクトは1つだけ（PDF全体）。

   ```bash
   npm run startup:set -- output/<名前>/<名前>-voice.json --source <元のファイル名>
   ```

   `public/examples/startup/` の中身（前に置いたプロジェクト）をすべて消して、`project.json` と説明の `startup.json` に置き換える。ファイルが壊れていたら何も消さずに止まる。開いているアプリは、ページを再読み込みすると新しいプロジェクトになる。

12. **動画にする**（頼まれたとき、またはPDFから動画を作るよう頼まれたとき）。

   ```bash
   npm run video:export -- output/<名前>/<名前>-voice.json output/<名前>/<名前>-voice.webm
   ```

   WebM（VP8・Opus）。音声のないプロジェクトは音声トラックなしで書き出す。最大60分（60ページ・1スライド60秒まで）。ナレーションのない動画は20分を超えても1本で書き出せる。ナレーション付きは全体20分以内（超えると音声生成が止まる）。音声は5秒ずつ処理し、動画は8MBのチャンクとBlobで保持する。10分を超えると100MB前後になり、書き出しに数分かかるので、バックグラウンドで実行する。初回だけ開発サーバーの準備でページが読み込み直され「Execution context was destroyed」で止まることがある。そのときはもう一度実行する。

   **書き出しが終わったら、必ずユーザーに知らせる。** ユーザーは待っている間に別の画面を見ていることが多く、確認の結果だけを書いても終わったことに気づかない。
   - 書き出しを始めるときに、終わったら知らせることと、かかる時間の目安を伝える。
   - 終わったら `npm run video:check -- output/<名前>/<名前>-voice.webm output/<名前>/work/check` で、長さ・大きさ・形式（VP8の映像とOpusの音声トラックがあること）を確かめる。途中の2コマ（25%と60%の位置）が `work/check/<名前>-voice-frame-<秒>s.png` に書き出されるので、Read で見て字幕とスライドが出ているかを確かめる。このプロジェクトはFFmpegを使わない方針なので、`ffprobe`・`ffmpeg` は使わない。
   - 通知を送る道具（`PushNotification` など。読み込まれていなければ ToolSearch で読み込む）があれば、それで「動画の書き出しが終わりました」と通知する。
   - 返信の1行目に「**動画の書き出しが終わりました。**」とはっきり書き、続けてファイルの場所（リンク）・長さ・大きさを伝える。
   - 失敗したときも同じように、すぐ知らせる。何が起きたかと、やり直したかどうかを書く。

13. **アプリを立ち上げる**（毎回行う。ユーザーに頼まれなくても、分析と書き込みが終わったら自動で行う）。手順11で置き換えた今回のプロジェクトを、ユーザーがすぐ見られるようにする。
   - アプリ内ブラウザ（`mcp__Claude_Browser__*`）があれば、`preview_start` に `{"name": "dev"}` を渡して開発サーバーを起動し、タブを開く（`.claude/launch.json` の `dev`）。すでに起動していれば、開いているタブを `navigate` で同じURLに読み直す。5173番が使われていると別の番号になるので、結果に出たURLを報告に書く。
   - アプリ内ブラウザがなければ、`npm run dev` を Bash のバックグラウンド（`run_in_background`）で起動し、表示されたURLを報告に書く。
   - 開いた画面（`computer` の `screenshot` か `read_page`）で、左上のプロジェクト名が今回の `<名前>` になり、1枚目の字幕が出ていることを確かめる。前のプロジェクトのままなら再読み込みする。

14. **報告する。** ページごとの部品と動き（主な部品と登場の順番、どの字幕に合わせたか、選んだ理由をひとこと）、部品に分けなかったページとその理由・カメラの動き、字幕、元のページとの差、新しく登録した読み方の一覧（表記 → 読み）、スライドの長さと合計時間（`voice:generate` の出力）、出力ファイルの場所。手順13で立ち上げたアプリのURL（今回のプロジェクトが最初から表示されていること）も伝える。あわせて次のことを伝える。
   - アプリでは字幕の文だけを直せる。読み上げ付きのスライドでは、時間は音声に合わせてあるので変えられない。
   - 文を直したら、画面の「音声生成」を押すか（`npm run dev` で開いたときだけ表示され、話す速さも選べる）、「保存」したファイルを渡して「音声を作り直して」と頼めば、直した字幕の音声だけを作り直す（「音声を作り直す」を参照）。
   - 動きは「2枚目の太陽をもっとゆっくり」、読み方は「AWSの読み方を直して」のように頼めば直せる。

## 動きを直す（ユーザーの指示で）

ユーザーは、スライドの番号と画面に見えているもの（「太陽」「見出し」「右の表」など）で、直したいところを伝えてきます。アプリには要素の一覧がないので、要素の名前はプロジェクトJSONや `work/elements.json` から探します。

1. **対象のプロジェクトを決める。** この会話で作った音声なしのものなら `output/<名前>/<名前>-captions.json`、ユーザーがファイルを示したらそれ。この会話で作ったナレーション入りなら `output/<名前>/<名前>-voice.json`。アプリの起動時に開いているもの（`public/examples/startup/startup.json` の `source` で分かる）は、`output/` にある元のプロジェクトを直してから、手順11（`startup:set`）で置き換える。どれか分からなければ尋ねる。
2. **今の動きを読む。** プロジェクトJSONの、そのスライドの `elements` から、名前・`animation`・`start`・`cue`・`enter`・`distance`・`loop`・`exit` を確かめる。`cue` がある部品は、その番号の字幕に合わせて出ている。ユーザーの言い方と名前が一致しないときは、位置や見た目から当たる要素を選び、どれを直したかを報告する。候補が複数あれば確かめる。
3. **指示を値に置き換えて `work/tune.json` に書く**（下の表）。指示があいまいなら、ふつうの範囲で一段階だけ変え、何をどれだけ変えたかを報告する。

   ```json
   {"slides":[{"index":2,"parts":{"太陽":{"enter":1.2},"見出し":{"start":0.6,"animation":"fade"}}}]}
   ```

4. **書き込む。** 変えられるのは動きの値（`animation`・`start`・`cue`・`cueOffset`・`enter`・`distance`・`loop`・`exit`・`exitDuration`）だけで、位置・見た目・スライドの長さ・字幕・音声は変わらない（ナレーション入りのプロジェクトでも音声の作り直しは要らない）。最後まで表示されていた要素は、登場時刻を変えても最後まで表示されたままになる。`cue` のある部品の時刻を `start` で決め直すときは `"cue": null` も一緒に書く。

   ```bash
   npm run elements:tune -- <project.json> output/<名前>/work/tune.json <project.json>
   ```

   コマンドは要素ごとに「前の値 → 新しい値」を表示する。

5. **`work/elements.json` があれば、同じ変更をそこにも書く。** あとで手順5（部品に分ける）からやり直したときに、直した動きが元に戻らないようにするため。
6. **確かめる。** 変えたスライドの登場を、手順5と同じ4コマで見る（`elements:build` をやり直すか、アプリで再生する）。起動時に開くプロジェクトだったなら手順11で置き換え直し、手順13でアプリを立ち上げる（起動していれば読み直す）。動画を作っていたなら手順12で書き出し直す。
7. **報告する。** スライド・要素ごとに、変えた値（前 → 後）と、それで見え方がどう変わるか。立ち上げたアプリのURLも伝える。

| ユーザーの言い方 | 変える値 |
|---|---|
| ゆっくり／ふわっと／落ち着いて | `enter` を0.3〜0.5秒増やす（上限3）。弾む動き（`pop`・`drop`）なら `fade`・`slide-up` などに変えてもよい |
| 速く／きびきび | `enter` を0.2〜0.3秒減らす（下限0.1） |
| 先に／早く出して | `start` を減らす（`cue` のある部品は `cue` を前の字幕にするか、`cueOffset` を減らす）。ほかの要素との順番が入れ替わるなら、それも報告する |
| 後で／最後に出して | `start` を増やす（`cue` のある部品は `cue` を後の字幕にするか、`cueOffset` を増やす） |
| 「〜と言うところで出して」／話に合わせて | その話をしている字幕の番号を `cue` にする（`cueOffset` は既定の-0.2秒のままでよい） |
| 大きく動かして／控えめに | `distance` を増やす／減らす（文字は30〜60、物は80〜140が目安）。`zoom`・`pop` なら `enter` も合わせる |
| 揺れを止めて／動き続けないで | `loop` を `none` |
| 揺らして／ふわふわさせて | `loop` を `sway`・`float`・`pulse` から選ぶ（1ページ1〜3個まで） |
| 別の出方にして | `animation` を「動きの付け方」の目安から選び直す。画像の部品に `lines`・`chars` は使えない（文字を1文字ずつ出したいという指示には、画像の部品なのでできないことと、代わりの `reveal`・`slide-up` を伝える） |
| 消えるようにして | `exit`（と `exitDuration`）を付ける |
| 動かさないで | `animation` を `none`、`loop` を `none` |

位置・大きさ・部品の切り分け方を変えたいという指示は `elements:tune` では直せない。`work/elements.json` の `box`・`key` を直して手順5から（字幕は手順8、音声は手順10で。音声は作成済みのものが使い回されるので、サーバーには頼まない）やり直す。`elements.json` がなければ、元のPDFから手順1でやり直すことになると伝える。

## 音声を作り直す・読み方を直す（ユーザーの指示で）

- **アプリで字幕を直したとき:** ユーザーがアプリの「保存」で保存したプロジェクトを受け取り、そのまま手順10に渡す（`npm run voice:generate -- <保存したファイル> output/<名前>/<名前>-voice.json`）。字幕の文が変わったところだけを作り直し、時間と `cue` の部品を合わせ直す。アプリで字幕を消した・足したときも同じ。続けて手順11・13（動画があれば12）を行う。
- **字幕を書き直すよう頼まれたとき:** `work/captions.json` を直し、手順8・9・10を順に行う（`captions:apply` の入力は `elements-project.json`）。
- **読み方を直すよう頼まれたとき**（「AWSをエーダブリューエスと読んで」「〇〇の読みが違う」）: `npm run reading -- 表記 読み` で登録し、手順10をやり直す。その語を含む字幕の音声だけが作り直される。辞書は全資料で共通なので、ほかの資料の読みにも効くことを伝える。
- **声・話す速さを変えたいとき:** `.env.local` の `IRODORI_VOICE`（登録した声のID。`none` は参照音声なし）・`IRODORI_CAPTION`（声の雰囲気の説明文）・`IRODORI_SPEED`（0.5〜2.0。1.1で約1割速い）を変えて手順10をやり直す。すべての字幕を作り直すので時間がかかることを先に伝える。`.env.local` はGitに含めない。

## 部品に分けるかどうか

- **分ける（既定）:** 単色や数色の平らな面の上に、見出し・本文・図・イラストの物が載っているページ。表紙・章の扉・イラスト入りのページ・図解・箇条書き。
- **分けない（カメラの動きにする）:** 写真が主役のページ（背景がグラデーションや質感で、色で切り分けられない）、細かい表やグラフ（部品にすると読む順番が崩れる）、文字がびっしりのページ。ユーザーがカメラの動きを望んだときも。
- ページの一部だけ分けてもよい。たとえば写真は台紙ごと1つの部品にして、見出しと本文だけ別に動かす。

## 部品の切り分け方（`elements.json`）

```json
{"slides":[{"id":"<slides.jsonのid>","background":{"animation":"none"},"parts":[
  {"name":"イラストの台紙","box":[0.59,0.075,0.955,0.925],"key":["#10272d"],"animation":"zoom","start":0,"enter":0.8},
  {"name":"コーヒーカップ","box":[0.645,0.395,0.94,0.725],"key":["#e7d6b8","#d69d68","#a8b395"],"animation":"pop","cue":2,"loop":"sway"},
  {"name":"見出し","box":[0.045,0.235,0.45,0.365],"key":true,"animation":"slide-up","start":0.3,"distance":60}
]}]}
```

| 値 | 意味 |
|---|---|
| `parts` | 部品の配列（1ページ39個まで）。**下にあるものから順に**並べる（台紙 → 台紙の上の物 → その上の物）。文字は最後でよい |
| `name` | 部品の名前（動きを直すときにこの名前で探す。画面で見て分かる名前にする。60字以内） |
| `box` | 部品を囲む四角 `[左, 上, 右, 下]`。方眼画像の目盛り（0〜1）で読む。物の端から1〜2%外側を囲み、ほかの物にはなるべくかけない |
| `key` | 部品の後ろにある面の色。この色に近い画素は透明になり、物の形だけが動く。`true` は四角のすぐ外側の色を自動で使う（周りが1色のとき。文字に向く）。色の配列（`"#rrggbb"`、6色まで）は、後ろに複数の面があるとき（台紙の色と夕日の色の上に湯気が載っている、など）。省略すると四角ごと動く |
| `tolerance` | `key` の色とどれだけ近ければ透明にするか（既定40、5〜150）。部品の色が背景の色に近いとき（クリーム色の紙とベージュの壁など）は14〜20に下げる |
| `fill` | `key` と使うとき: 抜いた跡を埋めるのに使う色を、`key` に挙げた色から選ぶ（1色または配列。既定はすべて）。台紙の端にある物で、台紙の外の色が跡に入り込むときに台紙の色だけにする。`key` なしのとき: 跡を塗る色（`"auto"`・`"#rrggbb"`・跡を残さない `"none"`） |
| `background` | 部品を抜いた後のページ全体（背景）の動き。地色だけになるので、ふつうは `{"animation":"none"}` |
| `animation`・`start`・`enter`・`distance`・`exit`・`exitDuration`・`loop` | 動き（次の節）。部品は画像なので `lines`・`chars` は使えない |

切り分けの仕組みと注意:

- 部品を抜いた跡は、同じ行の近くにある背景の色で埋まる。平らな面なら、部品が来る前も自然な画面になる。
- 台紙（イラストの枠など）の上に載っている物は、台紙と別の部品にできる。台紙の四角の中に完全に入っている物は、台紙を抜いた跡の中に自動で含まれる。
- 物どうしが重なるとき（カップの後ろに夕日がある、など）は、後ろの物を先に、前の物を後に並べる。後ろの物の隠れていた部分は推測で埋まるので、前の物が来る前は形が少し欠けて見えることがある。前後の物の登場時刻を近づけると目立たない。
- 文字は1行や1段落ずつ部品にする。見出しと本文を1つにまとめない。
- ロゴ・ページ番号・小さな飾りは、背景に残してよい（部品にしなくてよい）。

## 動きの付け方

| 値 | 意味 |
|---|---|
| `animation` | 登場の仕方: `fade`（ふわっと）/ `slide-up`・`slide-down`・`slide-left`・`slide-right`（その向きへ滑り込む）/ `pop`（弾んで出る）/ `zoom`（中心から広がる）/ `drop`（上から落ちて弾む）/ `blur`（ぼけから合う）/ `float`（ふわりと浮かび上がる）/ `reveal`（左から右へ現れる）/ `spin` / `none` |
| `start` | 登場する時刻（秒、スライドの始まりから）。省略すると並び順に0.25秒ずつずれる |
| `cue` | この番号の字幕（1から数える）が始まるときに登場する。ナレーションの長さは音声を作るまで分からないので、2文目以降の話に出てくる部品は `start` ではなく `cue` で決める。`start` より優先される |
| `cueOffset` | `cue` の字幕の始まりから、どれだけずらすか（秒、-3〜3、既定-0.2で話す少し前に出る）。同じ字幕で出る部品を0.2〜0.4秒ずつずらすのに使う |
| `enter` | 登場にかける秒数（0.1〜3、既定0.7） |
| `distance` | 滑り込む距離（px、既定140）。文字は30〜60、物は80〜140 |
| `loop` | 登場後に続ける小さな動き: `float`（上下にゆれる）/ `pulse`（ゆっくり脈打つ）/ `sway`（左右にかしぐ）/ `drift`（横に漂う）/ `spin` |
| `exit`・`exitDuration` | 退場の仕方と秒数。ふつうは付けない（次のスライドへの切り替えで消える） |

- **部品の種類ごとの目安:**
  - 台紙・イラストの枠・大きな図形 → `zoom`（`enter` 0.8）か `fade`。0秒から。
  - イラストの主役の物（カップ・人物・製品）→ `pop` か `slide-left`/`slide-right`。`loop` は `sway` か `float`。
  - 太陽・円などの背景の飾り → `zoom` か `drop`、`loop` は `pulse`。
  - 湯気・煙・光 → `float`、`loop` は `float`。
  - 線・ペン・矢印・下線 → `reveal`（左から右へ描かれるように見える）。
  - 小見出し → `slide-right`（`distance` 40）か `fade`。
  - 見出し → `slide-up`（`distance` 60）か `blur`。
  - 本文・箇条書き → `slide-up`（`distance` 30）か `fade`。箇条書きは1項目ずつ部品にして0.2〜0.3秒ずつずらす。
  - フッター・出典 → `fade`。
  - 図解・手順 → 読む順（左→右、上→下）に0.3〜0.5秒ずつずらして登場させる。
- **時間の流れ:** 見出し・小見出しと台紙は `start` で0〜0.4秒に置き、話し始め（0.5秒）より前に出す。1文目で話す物も `start` で0.4〜1.2秒に置く。2文目以降で話す物・本文・図の各部分は、その話をする字幕の番号を `cue` にして、話に合わせて出す。ナレーションのない背景の飾りや細かい物は1〜1.8秒に置く。どの部品も、その部品について話す字幕より遅く出さない。
- **音声なしで作るとき:** `cue` はそのまま使える（読む速さで割り当てた字幕の時間に合わせて出る）。
- **控えめに:** `loop` は1ページに1〜3個まで。同じ `animation` を同じページで3つ以上使わない。前後のページで主役の動きを変える（1ページ目は `pop`、2ページ目は `drop` など）。
- **字幕の帯:** 画面の下20%（方眼の y0.8 より下）は字幕の帯が重なる。大事な部品が下端にあるページは、その部品の登場を早めて、字幕が出る前に見せる。

## 字幕の書き方

字幕は、そのまま読み上げる原稿です。字幕1つが音声の1区切りで、話している間だけ画面に出ます。聞いて分かり、読んでも分かる文にします。

- 1スライドに2〜5個。1個は1文、句読点込みで全角20〜50字（上限120字、手動改行を含め12行以内、画面内に収まるよう文字サイズを自動調整）。1スライドの読み上げは60秒まで（1秒に約7文字）。資料の情報が多いページは5個まで使い、要点を選ぶ。
- 声に出して自然な話し言葉にする。かっこ・矢印・記号・箇条書きの体言止めは使わず、「〜です」「〜します」で言い切る。
- 数字・単位・英字は、読み上げたときに分かる書き方にする（「3つ」「約20%」）。読み方が紛れる語は、文を変えずに手順9の辞書で読みを決める。
- 画面の見出しや本文をそのまま繰り返さない。図や表が示していること、そのページで伝えたいことを補って説明する。
- 資料に無い事実・数値を足さない。読み取れない部分は推測で埋めない。
- 字幕の順番を、部品が登場する順番に合わせる（1文目は先に出る物、2文目は後から出る物について書く）。部品の `cue` は、その部品について話す字幕の番号にする。
- ページの流れがつながるように、前後のページとの関係を意識する。表紙・目次・まとめのページは短くてよい。
- です・ます調。落ち着いた説明の口調。絵文字は使わない。
- 書き直しを頼まれたら、`captions.json` を直して手順8・9・10を再実行する（時間は毎回割り当て直され、音声は変わった字幕だけ作り直される）。部品の動きを直すときは手順5からやり直す。

## カメラの動きの選び方（部品に分けなかったPDFページ）

部品に分けなかったページは1枚の画像なので、動かせるのはページ全体を映すカメラだけです。`captions.json` の `motion` の4つの値で決めます。

| 値 | 意味 |
|---|---|
| `type` | `zoom-in`（全体から注目点へ寄る）/ `zoom-out`（注目点から全体へ引く）/ `pan-left`・`pan-right`（拡大したまま横へ流す）/ `none`（静止） |
| `amount` | 強さ0〜1。寄りの最大倍率は 1+0.7×amount（1.0で1.7倍）。横移動は 1+0.6×amount 倍のまま動く |
| `focusX` / `focusY` | 注目点の位置0〜1（左上が0,0）。方眼画像の目盛りで読む。横移動では `focusY`（どの高さを流すか）だけを使う |

- **寄る場所**: そのページで一番伝えたいもの（結論の数字、グラフの山、図の中心、強調された語）の中心に置く。字幕が説明している対象と一致させる。
- **種類**:
  - 図・グラフ・写真が主役 → `zoom-in` でそこへ寄る。
  - 結論や全体像を最後に見せたい（部分から全体へ）→ `zoom-out`。注目点は最初に見せたい部分。
  - 横に長い表・年表・手順の並び → `pan-right`（左から右へ読む順）。`focusY` はその行の高さ。
  - 表紙・目次・文字だけのページ・まとめ → `none`、または `zoom-in` を `amount` 0.2〜0.3で。
  - 同じ種類が3ページ以上続かないようにし、流れに変化をつける。
- **強さ**: 落ち着いた動画が前提なので、ふだんは0.3〜0.6。細かい図を読ませたいときだけ0.7〜0.9。文字が多いページで強く寄ると、読ませたい文が画面外に出るので弱めにする。
- **話に合わせる**: 字幕が説明している対象に寄るので、1文目で話す対象を注目点にする。
- **字幕の帯**: 寄った後は注目点が画面の中央に来るので隠れないが、全体が映る場面（`zoom-in` の始め、`zoom-out` の終わり、`none`）では下端の内容が隠れることを意識する。下端が大事なページは `zoom-in` でそこへ寄る。
- 注目点がページの端に近いと、カメラはページ外を映さないよう内側へ寄せて止まる。端の内容を見せたいときは寄りを弱める。
